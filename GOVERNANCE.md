# Governance

The initial repository owner and release maintainer is the GitHub account `Lontkovsky`. No independent board, trustees, auditors or donors have been appointed. One owner currently controls source and releases; role separation in local software does not protect against a person controlling every key and host.

Maintainers approve product changes through issues and reviewed PRs. Release artifacts must identify source, toolchain, dependencies, tests and limitations. Infrastructure operators control availability and delivered client files. Credential authorities control admission and must be independently overseen. Trustees control decryption shares; production requires independent operators and a documented quorum. Observer operators retain and compare public evidence.

Transfer repository and release authority through a public governance issue with the identities and scope of incoming/outgoing maintainers, recorded approvals, key rotation and access revocation. Do not transfer private trustee keys to repository maintainers. Disclose funding and conflicts of interest before related decisions. There is no declared project funding at bootstrap.

Publish redacted incident reports, emergency client changes, cancellations and moderation reports. An undesired result is never a valid reason for invalidation. Content removal and cryptographic validity are separate decisions. Production adoption requires an explicit owner decision after the launch readiness review.
